# 法规清单数据字典

`manifest.csv` 使用 UTF-8，Excel 可通过“数据 → 从文本/CSV”选择 UTF-8 导入。含逗号或换行的内容须用 CSV 双引号包裹。脚本兼容 UTF-8 BOM。

| 字段 | 填写要求 |
|---|---|
| doc_id | DOC01、DOC02……按纳入顺序，不重新分配历史编号 |
| title | 官方全称，不加“候选”或自造版本名称 |
| short_name | 展示用简称 |
| issuer | 正式发布机构全称 |
| doc_type | 法律/行政法规/部门规章/规范性文件/自律规则/标准/解释材料 |
| authority_level | 前六类与手册一致；解释材料填“不适用” |
| document_number | 官方文号；确无文号填“无”；草案可填“待核” |
| publish_date | 对应这一版本的发布日期 YYYY-MM-DD |
| effective_date | 生效日期；解释材料无独立生效日期可留空并在 notes 说明 |
| expiry_date | 旧版失效日期；现行留空 |
| status | current/superseded/repealed/待核；按 scope.md 基准日判断 |
| replaced_by | superseded 必填存在的新版 DOC 编号；其他无替代时留空 |
| url | 官方文件详情页或附件的 http(s) 链接；不能填首页或搜索页 |
| fetched_at | 真实下载日期 YYYY-MM-DD |
| sha256 | 主原始文件的 64 位十六进制 SHA256 |
| local_path | 仓库相对路径 data/raw/DOCxx/DOCxx_简称_类型_版本状态.pdf |
| scope_tag | 核心/配套/旧版/解释 |
| notes | 纳入原因、主题、相关 DOC 编号、附件/OCR/HTML 转存、异常及核验说明 |

解释材料词表是对手册的明确补充：它不是新的法律效力层级。其 `status=current` 仅表示基准日所收录的解释版本；必须在 notes 声明“解释材料，不作主证据”。自律规则的非政府发布机构网站须先经人工核准，不能通过自动域名检查就断言来源已审核。

## 版本与证据

- 一个版本一个 DOC 编号，同名不同版本可以共存。禁止同一文件哈希重复入库。
- `superseded` 必须指向清单内另一份文件；旧版记准确失效日，不能因标题相似就认定替代。
- `repealed` 不强制存在替代文件，但须记录官方废止证据。
- 主原文哈希写 manifest；附件留在同一目录，并在 notes 记录文件名与哈希（可运行 hash_file.py 计算）。
- `relations.csv` 中 source 是作出引用/规定的文件，target 是被指向文件；关系限定为依据/适用/例外/修订。保留条款号、原文句和证据链接，不能从名称猜边。
- `verification_log.csv` 每次核验追加一行；result 使用通过/需修正/待核。复核人不得伪造或冒签。
- 日期格式检查和 URL 域名检查只能筛格式问题；需人工打开官网和附件确认内容完整及状态。

## 官网来源判定

脚本默认允许 `gov.cn`、`npc.gov.cn` 及其子域，使用真正的 URL 主机名判定，拒绝 `gov.cn.example.com` 这类伪装地址。其他确有必要的官方域名经人工确认后，用 `--official-domain 域名` 显式加入并记录依据。官方转载仍需核对来源和发布机关；搜索页/栏目页不得用作正式链接。

## 自动校验边界

草案模式允许空清单以及明确标注“待核”的版本元数据，已填行必须有真实原始文件及正确哈希。发布模式还检查总量、角色数量、至少 2 个历史版本、无待核、必填日期及基准日状态一致性。人工清单、覆盖关系、评审签字与附件齐全程度由团队核验，脚本不自动认定其完成。
